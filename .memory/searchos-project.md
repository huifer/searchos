The `~/git_repo/searchos` repo is the **implementation of SearchOS**, a Rust-native, extensible AI Search Infrastructure (Local Mode + Gateway Mode, Tavily-compatible, search memory, fault-isolated extension system).

**Why:** The project started from a ChatGPT share conversation that designed the system; the user asked to turn that conversation into polished, bilingual (中文/English) open-source-style docs, then to implement the RFC suite item by item.

**How to apply:**
- The canonical design is `docs/rfc/` (RFC-001..016 + parts 17-24 + RFC-026/027/028/029). The original design source is the ChatGPT share `https://chatgpt.com/share/6af0361a-d4bc-83ec-afb2-9a12023f5602`; the UI design source is `https://chatgpt.com/share/6af054b8-a43c-83ee-9218-d443cbac9f47`. Its 25-RFC suite + RFC-004 v1.1 + Visualization/Analytics RFCs were reconciled in `docs/gap-analysis.md`, annexes 23/24 and RFC-026..028. Treat `docs/rfc/` as source of truth.
- **Implementation status (2026-11): all Wave 0–4 items closed; the project is v1.0-GA-ready on the verified surface.** The remaining explicit non-goals are documented scope decisions, not missing work: WASM extensions, distributed/multi-node runtime, managed multi-tenant RBAC/SSO, a self-built global web index, browser engine, PDF/OCR, and additional providers (see `docs/feature-roadmap.md` §6). A complete Cargo workspace with all RFC-002 crates under `crates/`, plus `extensions/`, `fixtures/` (incl. the 500-question `dataset-v1.jsonl`), `tests/{integration,e2e,performance,compatibility}`, and `.github/` CI.

Schema is migration v5 (append-only; never edit released migrations). Frontend: `cd web && npm ci && npm run typecheck && npm run build && npm test` (51 Vitest tests).

- **ADR-027 (2026-11): user-selectable remote full-text backends.** `storage.fulltext` now accepts `tantivy` (default) | `elasticsearch` | `meilisearch` | `postgres` | `mysql`; connection settings live under `storage.remote.<backend>` (url/api_key/index/timeout_seconds/verify_tls), secrets via env (`SEARCHOS_ES_API_KEY`, `SEARCHOS_MEILI_API_KEY`). New crate `crates/searchos-index-remote` implements the `SearchIndex` port for all four; runtime holds `fulltext: Arc<dyn SearchIndex>` (plus `tantivy: Option<Arc<TantivyIndex>>` for diagnostics). SQLite stays the metadata source of truth; remote indexes stay rebuildable via `rebuild_from` (trait method added to `SearchIndex` alongside `commit`). Verified live against ES 8.15, PostgreSQL 16, MySQL 8.0 (ngram FULLTEXT, CJK works), Meilisearch v1.12.
- **RFC-029 / ADR-028 (2026-11): local data ingestion.** Local text / files / directories import into the same knowledge store as URL fetch. `IngestService` (`crates/searchos-application/src/ingest_service.rs`) is a sibling of `FetchService` and feeds the same `DocumentPort`, so versioning / chunking / outbox / workspace isolation / rebuild are inherited. Canonical URI `searchos-local://<workspace>/<source_key>` (source_key caller-supplied or content-addressed `sha256[:16]`); `Document` gained `source_type` + `title`; migration v4 adds `documents.source_type/title` + `ingest_jobs`/`ingest_job_items`, and v5 adds the Part 30 idempotency/cost/reservation recovery columns. `ContentCategory::Local` is never age-stale. Entries: CLI `searchos ingest --text|--file|--dir` and HTTP `POST /ingest`, `/ingest/file` (multipart), `/ingest/batch`, `GET /ingest/jobs/:id`. Bounds 20 MB/doc + 200 MB/batch; content-type sniffing + strict UTF-8 + HTML sanitization reuse the fetch path. `save_versioned` now takes `workspace_id` so `documents.workspace_id` is populated.
- **Part 30 / execution-correctness pass (2026-11):** all INV-30-01…21 invariants landed with named acceptance tests in `tests/integration/tests/rfc_gap_acceptance.rs` and unit tests. Hybrid retrieval is wired into runtime (`HybridRetriever` over Tantivy + LanceDB, RRF, canonical/semantic/retrieval/embedding/rerank caches); crawler selection + robots/Crawl-delay + failure isolation are wired into `FetchService`; memory search uses embedding + RRF and CLI `memory remember`; RFC-029 ingest returns 201, supports in-memory directory batches, pre-checks batch bounds, and is exposed over MCP; delete outbox events delete by chunk id and retry on index failure; budget reservations use a RAII guard; idempotency claims are atomic; cache keys include mode/freshness; canonical URL is one implementation; config fields are consumed/deprecated; fetch limits/DNS pinning/robots are enforced; trace fields are semantically true; conflict detection requires a shared claim; latency/cache/rate-limit structures are bounded. `docs/rfc-implementation-gaps.md` is retained as the historical register and marked resolved.
- **ADR-029 (2026-11): multi-key rotation for upstream providers.** `TAVILY_API_KEYS` / `BRAVE_API_KEYS` (comma/space separated) or `providers.<id>.api_keys` configure a key pool; `RotatingProvider` (`crates/searchos-provider/src/keyring.rs`) round-robins (default) or fails over (`rotation: failover`) across keys with per-key rate-limit/block/failure state. Registry and execution share the same adapter instance; keys are masked in all output (`tvly-****-abcd`). Verified with a live TCP mock upstream (429 on key #1 → key #2 succeeds, key #1 stays limited).

- **Analytics filter pushdown (2026-11):** `AnalyticsRepo::query_dataset` (`crates/searchos-storage-sqlite/src/repos.rs`) computes every Read Model live with the predicates in the SQL WHERE clause (`workspace_id`, `agent_id`, `provider_id`, `search_mode`, `quality_status`, `from`, `to`, `interval` bucketing). Unfiltered + `interval=day` reuses the precomputed `analytics_read_models` payload, and only when `AnalyticsRepo::needs_rebuild()` says the operational source watermark (max rowid of `search_tasks`/`cost_events`/`documents`/`document_chunks`/`embeddings`) has moved — no TTL/clock heuristic (a TTL was tried first and was unsound: an empty-but-fresh model skipped the rebuild and served zeros). Any predicate or a non-`day` interval forces the SQL path. Time bounds are normalized inside SQLite via `strftime('%Y-%m-%dT%H:%M:%f', …)` so RFC3339 `Z` and stored `+00:00` compare correctly. `meta` now carries `query_mode` (`precomputed`|`sql`), `data_freshness` (`complete`|`fresh`|`live`), `applied_filters`, `ignored_filters` (each with a reason), `refresh_skipped`, `model_age_seconds`. `quality_status` only derives `passed`/`failed` (audit trail) and `partial` (task status); anything else is reported as ignored. Named tests: `unfiltered_live_query_matches_the_precomputed_read_model`, `time_range_and_interval_are_pushed_into_sql`, `workspace_and_mode_filters_are_pushed_into_sql`, `quality_status_filter_uses_the_quality_gate_audit`, `cursor_watermarks_the_request_table`, `precomputed_payload_is_reused_only_while_the_watermark_is_unchanged`, `filters_absent_from_a_dataset_are_reported_not_applied`, plus `dashboard_filters_are_pushed_into_sql_and_reported` in the HTTP crate. 488 tests pass on the release commit.

- **Tavily compatibility contract (2026-11):** frozen subset documented in `docs/tavily-compatibility.md` and enforced by `fixtures/tavily/*.json` + `tests/compatibility/tests/tavily_contract.rs` (9 cases). `TavilySearchRequest` now reports every documented-but-unhonored knob (`search_depth`, `include_answer`, `include_raw_content`, `include_images`, `chunks_per_source`, `time_range`, `country`, `include_favicon`, `auto_parameters`, `model`, `include_usage`) AND every unknown field via `#[serde(flatten)] extra`; `unsupported_features` is always serialized (even when empty). Verified live.
- **MCP transport decision / ADR-031 (2026-11):** v1 speaks MCP **stdio only**. The stale claims (`docs/architecture.md` "HTTP API / remote MCP", README "REST + MCP") are fixed; the contract lives in `docs/mcp.md` and the ADR in `docs/rfc/part-19-adr-decisions.md` §19.5. Rationale: remote-MCP hosts already speak HTTP and can use REST/Tavily today; a second HTTP surface would add session/resumability/Mcp-Session-Id/per-stream-SSE/origin-validation cost for no new capability, and a separate listener would duplicate the gateway auth+workspace+rate-limit stack. `searchos_interface_mcp::TRANSPORT == "stdio"` is now a public constant. `notifications/cancelled` is no longer silently dropped: it increments `mcp.cancellation_unsupported_total` and logs to stderr (v1 handles requests inline, so there is nothing in flight to cancel) — stdout stays JSON-RPC-only. Gate: `tests/compatibility/tests/mcp_transport.rs` (transport declaration, MCP crate has no HTTP server dependency, gateway has no MCP route, docs don't claim remote MCP, tool catalogue stable, cancellation acknowledged). Live-verified: initialize / tools/list (10 tools) / tools/call over stdio with the cancellation warning on stderr only.
- **Gateway lifecycle + Prometheus metrics (2026-11):** `GET /metrics` serves Prometheus text exposition 0.0.4 (`searchos_*`: search/quality/cost/outbox counters, latency percentiles in seconds, status counts as the only labelled series, every Part 30 invariant as `searchos_invariant_*`, plus `searchos_uptime_seconds`, `searchos_sse_active`, `searchos_sse_connections_total`, `searchos_index_outbox_pending`, `searchos_schema_version`, `searchos_build_info{version,schema_version}`). Rendering lives in `searchos_observability::render_prometheus(snapshot, &ServerMetrics)`; `MetricsSnapshot` gained raw counts so exporters do not reconstruct them from rates. Auth is the same bearer token as every other endpoint. Graceful shutdown: SIGTERM/SIGINT stops accepting, drains in-flight requests, **terminates SSE streams** (they watch `AppState.shutdown`; without that the drain hangs forever on an open stream — found by the e2e test), then flushes the outbox once and exits 0; a second signal force-exits. `run_outbox_worker` is extracted for testing. Gates: `tests/e2e/tests/gateway_lifecycle.rs` (real process: /metrics content, SIGTERM exit 0, SIGTERM with an open SSE stream), `outbox_worker_drains_pending_rows_on_shutdown`, `metrics_endpoint_serves_prometheus_text`, `shutdown_signal_resolves_when_flipped`, plus the observability renderer tests.

- **Docker / compose deployment (2026-11, verified by real builds):** `Dockerfile` is a four-stage build — `rust-build` (rust:1.97-slim + build-essential + protobuf-compiler + **libprotobuf-dev** + pkg-config; `cargo build --release --locked --bin searchos` with BuildKit cache mounts), `console-build` (node:22-alpine: `npm ci` → `npm run build` → `npm prune --omit=dev`), `gateway` (debian:bookworm-slim + tini PID 1 + curl healthcheck, 608MB) and `console` (node:22-alpine, `USER node`, 1.03GB). MCP stays stdio-only so there is deliberately no MCP container (ADR-031). Verified live: both images built; gateway container returns `/health` + `/metrics`, ingest→search works, `docker stop` exits 0 in 0.17s with "gateway shut down cleanly", restart keeps the document; the compose stack serves the console `/` and its server-side proxy returns gateway JSON, and Prometheus reports target `searchos-gateway` health=up and `searchos_search_requests_total = 2` after activity. - **Release automation + CHANGELOG + CI gates (2026-11):** `.github/workflows/release.yml` runs on `v*` tags — it asserts the tag matches the workspace `version`, re-runs the CI gates, builds a release binary with SHA-256 checksums, builds multi-arch gateway/console images (pushed to GHCR when `REGISTRY_TOKEN` is set, otherwise built locally), and creates a GitHub release whose body is that version's `CHANGELOG.md` section. CI gained two jobs: `eval-gate` (ingests the deterministic seed corpus from `fixtures/evaluations/generate_seed.py`, runs 20 real evaluations, and `scripts/check_eval_gate.py` asserts keyword coverage / pass rate / p95 latency / that baseline C is a live run) and `backup-drill` (`tests/e2e/tests/backup_restore.rs`). **Two real bugs the drill found and fixed:** (1) `backup create` copied the bare `.db` file, so committed transactions still in the WAL were missing from the snapshot — it now uses `VACUUM INTO`; (2) `backup restore` initialised a runtime first (opening an empty database) and that connection's WAL checkpointed over the restored snapshot on exit — restore is now a config-only file operation that never opens the database, and it removes stale `-wal`/`-shm` sidecars.
